# A1 — Realistic, Compliant Toolchain for Mining Vertical Audience Pain Points (2025–2026)

**Scope:** Solo technical founder doing e-commerce/service product discovery. Platforms: X (Twitter), TikTok, Facebook/Meta, Reddit, plus Amazon reviews. Includes legal-risk realities and build-vs-buy.
**Researched:** 2026-06-10. ~14 web searches; official docs (developer.x.com, docs.x.com, support.reddithelp.com, apify.com actor pages) were 403-blocked from this sandbox, so several claims rest on multiple convergent secondary sources — flagged in confidence ratings.

---

## 1. X (Twitter) API — pricing and viability

**The big change: X killed fixed tiers for new developers in early 2026 and moved to pay-per-use.**

- X announced a **pay-per-use pricing pilot** (devcommunity.x.com thread "Announcing the X API Pay-Per-Use Pricing Pilot", and a follow-up "Announcing the Launch of X API Pay-Per-Use Pricing"). Multiple secondary sources date the transition to **January 21 – February 2026**: pay-per-use is now the **default for new developers**; the free tier is effectively discontinued; Basic/Pro are **legacy-only** (existing subscribers keep them). Sources: [Medianama (Feb 2026)](https://www.medianama.com/2026/02/223-x-developer-api-pricing-pay-per-use-model/), [Postproxy](https://postproxy.dev/blog/x-api-pricing-2026/), [Blotato](https://www.blotato.com/blog/twitter-api-pricing), [twitterapi.io breakdown](https://twitterapi.io/blog/x-api-cost-breakdown-2026), [X dev forum announcement](https://devcommunity.x.com/t/announcing-the-launch-of-x-api-pay-per-use-pricing/256476). **Confidence: high** (official forum thread exists + 5 independent secondary sources agree).
- **Pay-per-use rates:** **$0.005 per post read**, **$0.01 per post created**, hard cap **2,000,000 reads/month** (above that → Enterprise). As of an **April 20, 2026** update, "owned reads" (your own posts/bookmarks/followers/lists) dropped to **$0.001 per resource**. Sources: [docs.x.com pricing page](https://docs.x.com/x-api/getting-started/pricing) (403 from sandbox, surfaced via search), [Postproxy](https://postproxy.dev/blog/x-api-pricing-2026/), [TweetStream](https://tweetstream.io/blog/twitter-api-pricing), [Sorsa](https://api.sorsa.io/blog/twitter-api-pricing-2026). **Confidence: high on the $0.005/read headline; medium on the April 2026 owned-reads detail** (fewer sources).
- **Legacy tiers (context / existing subscribers only):** Free tier ≈ **500 posts write/month, ~100 reads/month, 1 request per 24h on most endpoints** — useless for mining. **Basic: $200/month** (doubled from $100 in **Oct 2024**, reads raised from 10,000 → **15,000 posts/month** — [TechCrunch, Oct 30 2024](https://techcrunch.com/2024/10/30/x-makes-its-basic-api-tier-more-costly-launches-annual-subscriptions/)). **Pro: $5,000/month, 1M posts read/month** + full-archive search. Note conflict: some pages still quote Basic at $100/10K (pre-Oct-2024 figures); the $200/15K numbers are the post-change ones. Sources: [TechCrunch](https://techcrunch.com/2024/10/30/x-makes-its-basic-api-tier-more-costly-launches-annual-subscriptions/), [xpoz.ai tier comparison](https://www.xpoz.ai/blog/guides/understanding-twitter-api-pricing-tiers-and-alternatives/), [Jesus Iniesta tier guide](https://jesusiniesta.es/blog/x-api-pricing-tiers-what-you-actually-get). **Confidence: high** (TechCrunch is primary-adjacent).

**Economic viability for pain-point mining:** Marginal-to-poor.
- Pain-point mining is read-heavy. Reading 50,000 posts/month (a modest keyword-listening workload across a few niches) = **$250/month** at $0.005/read. 500K reads = $2,500/month. The old Basic tier's 15K reads/month was too small for mining anyway; Pro at $5K/month was never solo-founder territory.
- Search endpoint access historically required Basic+ (recent search only; full-archive was Pro/Enterprise). Under pay-per-use every matched post you pull costs you. For broad exploratory listening, X is now the **most expensive mainstream source per data point**. Indie-hacker commentary reaches the same conclusion ([wearefounders.uk: "The X API price hike: a blow to indie hackers"](https://www.wearefounders.uk/the-x-api-price-hike-a-blow-to-indie-hackers/), [Superframeworks](https://superframeworks.com/articles/x-api-pay-per-use-pricing-indie-hackers)). **Confidence: high** (arithmetic from verified rates).
- A gray-market alternative ecosystem exists (twitterapi.io, sociavault, etc., often ~$0.15–0.25 per 1K tweets) but these are unofficial scrapers wearing API clothing — ToS risk transfers to you. **Confidence: medium.**

**Verdict:** Usable for *targeted* checks (e.g., read 5–10K posts on one niche keyword = $25–50), not for always-on broad listening. Budget option: pay-per-use with tight query discipline.

## 2. TikTok — official access vs. scrapers

**Official Research API: not available to you.**
- Eligibility is restricted to **academic researchers at qualifying institutions (US, EEA, UK, Switzerland), EU-registered non-profits, and Brazilian academic/non-profit youth-safety researchers**. Applicants "must be independent from commercial interests" and conduct research on a **non-commercial, public-interest** basis. **"Creators, advertisers, and commercial users are not eligible."** Sources: [developers.tiktok.com Research API page](https://developers.tiktok.com/products/research-api/), [Research API FAQ](https://developers.tiktok.com/doc/research-api-faq). **Confidence: high** (official docs, current). A solo commercial founder has **zero official read-API path** for TikTok comments/hashtags.

**Third-party scrapers (Apify) — the de facto channel:**
- Apify hosts many TikTok actors. Comment scrapers range **$0.20–$5.00 per 1,000 comments** depending on actor: [clockworks/tiktok-comments-scraper](https://apify.com/clockworks/tiktok-comments-scraper) ≈ **$5/1K** ($0.005/item, pay-per-result); [epctex](https://apify.com/epctex/tiktok-comment-scraper), [automation-lab](https://apify.com/automation-lab/tiktok-comments-scraper), [codescraper](https://apify.com/codescraper/tiktok-comments-scraper) ≈ **$1/1K**; [kawsar](https://apify.com/kawsar/tiktok-comments-scraper) ≈ **$0.20/1K**. Hashtag scraping: [clockworks/tiktok-hashtag-scraper](https://apify.com/clockworks/tiktok-hashtag-scraper) ≈ **$5/1K videos**; the general [clockworks/tiktok-scraper](https://apify.com/clockworks/tiktok-scraper) ≈ **$1.70/1K results** per [use-apify.com comparison](https://use-apify.com/docs/best-apify-actors/best-tiktok-scrapers). Apify free plan includes **$5 usage credit/month** ([apify.com/pricing](https://apify.com/pricing)). **Confidence: medium-high** (actor pages confirmed via search snippets; prices on Apify change frequently — verify on each actor's Pricing tab).
- Practical cost: 100 niche videos × 200 top comments = 20K comments ≈ **$4–$20/month**. Cheap.

**Legal/ToS reality:**
- Scraping violates TikTok ToS; TikTok deploys CAPTCHAs, rate limiting, device/network fingerprinting, and IP blocks, and bans accounts caught scraping while logged in ([TikTok privacy blog: "How We Combat Unauthorized Data Scraping"](https://www.tiktok.com/privacy/blog/how-we-combat-scraping/en)). **Confidence: high.**
- Enforcement against small actors is technical (blocks/bans), not legal: "lawsuits for public data scraping are rare and expensive... typically reserved for large-scale commercial operations"; TikTok's enforcement is "less systematic" than Meta/X ([ScrapeCreators platform-by-platform guide](https://scrapecreators.com/blog/what-happens-when-social-media-companies-catch-you-scraping-a-platform-by-platform-guide)). **Confidence: medium** (practitioner source, consistent with absence of reported TikTok-v-small-scraper suits).
- Case law: **hiQ v. LinkedIn** (9th Cir. 2022) held scraping **public** data does not violate the CFAA's "without authorization" clause — but hiQ ultimately **lost on breach-of-contract/trespass grounds**, agreed to a permanent injunction and a **$500,000 judgment** (Dec 2022 consent judgment). Lesson: public scraping isn't "hacking," but logged-in scraping that breaches a ToS you accepted creates real contract/tort liability. Sources: [Wikipedia: hiQ Labs v. LinkedIn](https://en.wikipedia.org/wiki/HiQ_Labs_v._LinkedIn), [Proskauer settlement note, Dec 8 2022](https://newmedialaw.proskauer.com/2022/12/08/hiq-and-linkedin-reach-proposed-settlement-in-landmark-scraping-case/), [ZwillGen "lessons learned"](https://www.zwillgen.com/alternative-data/hiq-v-linkedin-wrapped-up-web-scraping-lessons-learned/), [Morgan Lewis](https://www.morganlewis.com/blogs/sourcingatmorganlewis/2022/12/linkedin-v-hiq-landmark-data-scraping-suit-provides-guidance-to-data-scrapers-and-web-operators). **Confidence: high.**

**Verdict:** No compliant official path; Apify actors are cheap, effective, and the realistic risk for a solo founder doing low-volume public scraping is IP blocks/account bans, not litigation — but it is technically a ToS violation. Use logged-out/public-only scraping via a third party (risk concentrates on the actor operator), keep volumes modest, store only what you need.

## 3. Facebook/Meta — public groups and comments

**Official API: door closed.**
- Meta **deprecated the Groups API in Graph API v19.0** (announced Jan 23, 2024); all group content retrieval ended **April 22–23, 2024**, including `publish_to_groups` and `groups_access_member_info`. Sources: [TechCrunch, Feb 5 2024](https://techcrunch.com/2024/02/05/meta-cuts-off-third-party-access-to-facebook-groups-leaving-developers-and-customers-in-disarray/), [Ayrshare](https://www.ayrshare.com/facebook-removes-groups-api-access-impact-and-implications/), [Sprinklr help](https://www.sprinklr.com/help/articles/getting-started-facebook/meta-deprecates-facebook-groups-api/66229eb25f9dd9599d632712). **Confidence: high.** There is **no official way** to programmatically read group content in 2025–2026. (Pages/owned-asset data via Graph API still exists but is irrelevant to mining other people's groups.)

**Scrapers:**
- Apify actors exist for **public groups only**: official [apify/facebook-groups-scraper](https://apify.com/apify/facebook-groups-scraper) ≈ **$2.60 per 1,000 posts**; community actors from ~**$1.50/1K** (e.g., [memo23/facebook-public-group-posts-scraper](https://apify.com/memo23/facebook-public-group-posts-scraper), no cookies/login). **Confidence: medium-high** (search-snippet-confirmed; verify live pricing). Private groups require logged-in session cookies — much higher ToS/ban risk and arguably outside the hiQ/Bright-Data "public data" safe-harbor logic.

**Risk level:**
- **Meta v. Bright Data (N.D. Cal., Jan 2024):** court granted summary judgment **against Meta** — its ToS only bind **logged-in** users; "Meta's terms do not apply to the scraping of public information while logged out." Meta **dropped the suit and waived appeal in Feb 2024**. Sources: [TechCrunch, Jan 24 2024](https://techcrunch.com/2024/01/24/court-rules-in-favor-of-a-web-scraper-bright-data-which-meta-had-used-and-then-sued/), [TechCrunch, Feb 26 2024](https://techcrunch.com/2024/02/26/meta-drops-lawsuit-against-web-scraping-firm-bright-data-that-sold-millions-of-instagram-records/), [Farella Braun + Martel analysis](https://www.fbm.com/publications/major-decision-affects-law-of-scraping-and-online-data-collection-meta-platforms-v-bright-data/). **Confidence: high.**
- Caveats: (a) most valuable niche groups are **private** → off-limits without logged-in scraping, which puts you back in ToS-breach territory; (b) Meta is historically the **most litigious** platform against scrapers; (c) group posts contain personal data → GDPR/CCPA exposure if you store/repurpose it.

**Verdict:** Worst risk/effort-to-signal ratio of the four. Public-group scraping is legally defensible post-Bright-Data and cheap via Apify, but coverage is poor (best groups are private) and Meta is aggressive. Treat as a manual, browse-and-take-notes channel, not a pipeline.

## 4. Reddit — still the best official channel, but the door is narrowing

- **Free tier survives:** free access for **non-commercial** use at **100 queries/minute per OAuth client ID** (averaged over a 10-min window; 10 QPM unauthenticated). Paid/commercial: **$0.24 per 1,000 API calls** (the 2023 price that killed Apollo), commercial use requires written approval. Sources: [Reddit Data API Wiki](https://support.reddithelp.com/hc/en-us/articles/16160319875092-Reddit-Data-API-Wiki), [Octolens breakdown](https://octolens.com/blog/reddit-api-pricing), [Data365](https://data365.co/blog/reddit-api-limits). **Confidence: high** (official wiki + convergent secondaries).
- **NEW — 2025 crackdown:** Reddit's **Responsible Builder Policy (updated Nov 11, 2025)** requires **pre-approval for ALL new API access**, including personal/hobby projects: application describing purpose, implementation, data usage; ~**2–4 weeks** turnaround; **AI/ML training on Reddit data prohibited** without consent. Pre-Nov-2025 OAuth credentials still work for now. Sources: [Responsible Builder Policy (support.reddithelp.com)](https://support.reddithelp.com/hc/en-us/articles/42728983564564-Responsible-Builder-Policy), [ReplyDaddy analysis](https://replydaddy.com/blog/reddit-api-pre-approval-2025-personal-projects-crackdown), [molehill.io](https://molehill.io/blog/reddit_killed_self-service_api_keys_your_options_for_automated_reddit_integration). **Confidence: high on the policy's existence/date; medium on the 2–4 week timeline** (single secondary source).
- **The GummySearch signal:** GummySearch — *the* Reddit pain-point tool — **shut down Nov 30, 2025** because it "was not able to reach an agreement that aligns with Reddit's Data API usage policies" for a commercial license, after serving 135K+ users ([gummysearch.com/final-chapter](https://gummysearch.com/final-chapter/), [gummysearch.com/closing-time](https://gummysearch.com/closing-time/)). **Confidence: high.** Implication: Reddit now refuses/prices-out even mid-size commercial users of its data. A personal research tool is still approvable; a *product built on* Reddit data is platform-risk roulette.
- Historical archive: Pushshift was cut off mid-2023 (now mod-only); its dumps live on Academic Torrents; community successor **PullPush** exists ([pullpush-io.github.io](https://pullpush-io.github.io/), [HN thread](https://news.ycombinator.com/item?id=36038684)). Gray-zone for ToS but useful for historical niche analysis. **Confidence: high.**

**Is pain-point mining viable and free?** **Yes — uniquely so.** 100 QPM ≈ 144K calls/day; each listing call returns up to 100 posts/comments. A solo founder's internal-research use is plausibly "non-commercial use of the Data API" in the sense Reddit polices (you're not redistributing data or selling a data product), though strictly Reddit could read any business-purpose use as commercial — apply honestly, describe it as internal market research, don't resell data, don't train models on it. **Confidence on interpretation: medium** (policy language is vague by design).

## 5. Signal-to-noise ranking for purchase-intent pain points

No rigorous head-to-head study exists; this synthesizes practitioner writeups. **Confidence: medium overall** (practitioner consensus, not measured data).

1. **Amazon negative reviews (1–3★)** — highest purchase-intent signal per unit effort: every reviewer is a *verified buyer* describing why a product failed them. Kellogg-cited finding: insights from Amazon review mining matched focus-group output on almost all topics ([CedCommerce 2026 product-research guide](https://cedcommerce.com/blog/amazon-product-research-in-2026-tiktok-discovery-amazon-query-data-and-ai-validation/)). The copywriting/ecom canon since Copyhackers' review-mining method ([copyhackers.com, orig. 2014, still canonical](https://copyhackers.com/2014/10/amazon-review-mining/)) treats 1–3★ mining for "repeated complaints, feature gaps, unmet needs" as the standard differentiation play; Helium 10 productizes it ([helium10.com](https://www.helium10.com/blog/succeed-with-amazon-product-review-data/)). Caveat: only covers *existing* product categories; Amazon blocks scrapers (use Apify/Helium-10-class tools or manual reading).
2. **Reddit niche subreddits** — best for *unserved* gaps and raw frustration: "brutally honest," "help-me-find" posts describe unmet demand directly; validation heuristic = same complaint across multiple subreddits/timeframes with upvotes ([Inc.com on founders mining Reddit](https://www.inc.com/diana-bocco/reddit-customer-pain-point-founders-best-product-ideas/91352669), [Peekdit step-by-step](https://www.peekdit.com/blog/how-to-find-product-ideas-on-reddit), [PainOnSocial methodology](https://painonsocial.com/blog/reddit-pain-point-analysis)). Weaker on purchase intent than Amazon (complainers ≠ buyers), strongest on problem discovery.
3. **Facebook groups** — high signal in older/parent/local/hobbyist demographics that barely exist on Reddit, but locked behind privacy; effectively manual-only (see §3).
4. **TikTok comments** — good for emerging consumer-product demand ("where do I buy this," "I need this for X") and trend velocity; very noisy, short, low context; cheap to harvest at scale via Apify, so worth including as a bulk-LLM-filter channel.
5. **X** — lowest value per dollar for e-commerce pain points in 2026: consumer product chatter is thin relative to tech/news/finance, and reads now cost $0.005 each. Use only for targeted brand-complaint checks.

| Tool | Status / Pricing | Coverage | Notes |
|---|---|---|---|
| **GummySearch** | **DEAD** — closed Nov 30, 2025; data deleted Dec 2026 ([final chapter](https://gummysearch.com/final-chapter/)) | Reddit | Was $29–199/mo. Killed by Reddit licensing. |
| **SparkToro** | Free (5 searches/mo); **~$50/mo Personal, $150 Business, $300 Agency** (one source cites $38/$112 — likely annual-billing rates; 25% annual discount) ([sparktoro.com/pricing](https://sparktoro.com/pricing), [topsocialtools review](https://www.topsocialtools.com/insights/sparktoro/)) | Audience profile: which sites/podcasts/subreddits/keywords an audience uses | Audience *demographics & hangouts*, not pain-point text mining. Complementary, not a substitute. **Confidence: medium** (sources conflict on exact price). |
| **F5Bot** | **Free** ([via RedShip comparison](https://redship.io/best-gummysearch-alternatives)) | Reddit + HN keyword email alerts | Best free monitoring primitive. |
| **Syften** | Low-cost paid | Reddit, HN, Slack groups, more | Closest cheap GummySearch-monitoring replacement. |
| **PainOnSocial** | Request-access pricing ([painonsocial.com](https://painonsocial.com/blog/gummysearch-alternatives-reddit-market-research)) | Reddit pain-point scoring (0–100) | Direct pain-mining successor; unproven. |
| **RedShip / Replymer / Subreddit Signals / Redreach** | $19–$699/mo ([prowlo roundup](https://prowlo.com/blog/gummysearch-shut-down-what-now), [redship.io](https://redship.io/best-gummysearch-alternatives)) | Reddit marketing/lead-gen | Mostly engagement/lead tools, not research. Post-GummySearch ecosystem is churning; all carry the same Reddit platform risk that killed GummySearch. |
| **Helium 10 / Jungle Scout** | ~$39–99/mo | Amazon reviews, keywords | The Amazon-side review-mining standard. |

**Build vs. buy for a solo technical founder:** Build a thin pipeline. Rationale: (1) the category leader was just killed by platform risk — paying $50–250/mo for a tool that may lose its data source is poor EV; (2) the compliant free core (Reddit OAuth app @ 100 QPM + Apify TikTok comments @ ~$1/1K + manual Amazon 1–3★ reading + F5Bot alerts) costs **≈ $0–20/month** plus LLM tokens for clustering/classification; (3) your edge is custom taxonomies per vertical, which SaaS can't do. Buy SparkToro only when you need audience-demographics validation for a niche you've already found.

## Recommended stack (solo founder, ≤$50/month, compliance-ranked)

1. **Reddit (official, free):** register OAuth app under the Responsible Builder process now (2–4 wk lead time), describe as internal market research, no AI-training, no redistribution → PRAW/raw OAuth at 100 QPM. Backbone of the pipeline.
2. **Amazon 1–3★ reviews:** manual + Helium 10-class tooling per candidate category. Highest purchase-intent signal.
3. **TikTok comments via Apify** (~$1/1K, $5 free credit): hashtag → top videos → comments; bulk-classify with an LLM. Accept low ToS risk (public data, third-party actor).
4. **F5Bot (free)** for always-on keyword alerts; **SparkToro free tier** for audience-hangout validation.
5. **X:** pay-per-use only for surgical queries (≤10K reads ≈ $50). **Facebook groups:** manual browsing only; skip pipeline automation.
